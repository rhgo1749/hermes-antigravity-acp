# Generic install and recovery guide

This document covers the reusable user-scoped installation path only. It does not
record live host, account, or profile deployment state.

## Install and update

From a checkout on a supported platform, run:

```bash
python3 scripts/install_acp.py install
python3 scripts/install_acp.py verify
```

`install` and `update` install the registry-pinned official server and register
the provider under the selected Hermes home. Repeating either action is safe:
versioned server directories are retained, the launcher is updated only when
needed, and an already-current provider copy is left unchanged. Replaced provider
code is backed up outside the Hermes plugin-discovery tree.

The generic path does not call Docker, use sudo, select an account mux, import
private deployment policy, or modify Hermes configuration, authentication,
account registries, conversations, or session databases. The optional portfolio
policy is an independent extension and is not installed by this path.

## Verification

`python3 scripts/install_acp.py status` reports whether the official server,
launcher, provider manifest, and executable are present. `verify` checks the
provider registration and launcher target, then its probe sends only the
unauthenticated ACP `initialize` request; the harness itself performs no
login and sends no authentication exchange or prompt.

Credential-free protocol behavior is exercised separately by the fake ACP
subprocess tests. Live account authentication is not a prerequisite for
installation or the initialize probe.

## Recovery

If a provider update needs to be reversed, use the installer from the previously
pinned release checkout and run `python3 scripts/install_acp.py install` (or
`update`) with the same Hermes home and install paths. Official binaries are
versioned rather than overwritten, and the previous provider directory is kept
under `plugin-backups` outside plugin discovery. Inspect that backup before any
manual restoration. Run `verify` after recovery.

Do not remove or rewrite conversation/session state, authentication files,
account registries, or user configuration as part of installer recovery. No
rollback or deployment is performed automatically by this documentation.
